# Excluded Large Files & Build Artifacts

This document explains which large files are intentionally NOT included in the Git repository and why.

## 📊 Summary

| Category | Total Size | Reason | Installation |
|----------|-----------|--------|--------------|
| Build artifacts | 100-500 MB | Auto-generated | `make clean` before commit |
| Tool binaries | 3-5 GB | Large; platform-specific | Package managers or build scripts |
| Simulation outputs | 500 MB - 2 GB | Temporary; reproducible | Re-run simulations |
| PDK files | 1-3 GB | License-restricted | Download separately from ASAP7 |
| Cache files | - | Not needed | Auto-generated when needed |
| **TOTAL** | **~5-10 GB** | - | - |

---

## 🚫 Excluded Directories & Files

### 1. Tool Binaries & Prebuilt Binaries

**Path**: `vercore_sandbox/tools/` (and similar)

**Size**: ~3-4 GB

**Contents**:
- `vercore_sandbox/tools/OpenROAD/` - Compiled OpenROAD binary
- `vercore_sandbox/tools/yosys/` - Compiled Yosys binary
- `vercore_sandbox/tools/verilator/` - Verilator binaries
- `vercore_sandbox/tools/riscv-*/` - RISC-V cross-compiler toolchain

**Why Excluded**:
- Binary files are platform-specific (Linux x64 only)
- Repository becomes unusable on other architectures (ARM, macOS, Windows)
- Can be easily installed via `apt-get` or build scripts
- Size makes cloning/pulling impractical
- Version management better handled by package managers

**How to Install**:
```bash
# Use package managers
sudo apt-get install -y yosys verilator gcc-riscv64-unknown-elf

# Or use provided scripts
bash vercore_sandbox/scripts/install_spike.sh
bash vercore_sandbox/scripts/install_openroad_binary.sh
```

### 2. Build & Compilation Artifacts

**Paths**:
- `vercore_sandbox/build/` (Verilator-generated C++ files)
- `vercore_sandbox/results/` (Place & Route outputs)
- `vercore_sandbox/logs/` (OpenROAD flow logs)

**Size**: 100-500 MB per run

**Contents**:
- `obj_dir/` - Verilator C++ generated source
- `*.o`, `*.a` - Object and archive files
- `sim_vercore` - Compiled simulator executable
- `*.vcd`, `*.fst` - Waveform files
- `6_1_cts.def`, `6_1_routed.def` - Design exchange format files
- `design.gds` - GDSII mask files (very large)

**Why Excluded**:
- Auto-generated during build
- Not needed; can be regenerated with `make`
- Changes frequently; causes unnecessary commits
- Very large waveforms (VCD files can be GBs)
- GDSII files are specific to this tape-out

**How to Regenerate**:
```bash
cd vercore_sandbox
make clean              # Remove old artifacts
make test_all           # Rebuild tests
make -C OpenROAD-flow-scripts/...  # Rerun place & route
```

### 3. OpenROAD Physical Design Outputs

**Paths**:
- `vercore_sandbox/OpenROAD-flow-scripts/results/`
- `vercore_sandbox/OpenROAD-flow-scripts/logs/`

**Size**: 500 MB - 2 GB per design run

**Contents**:
- Intermediate DEF files (floorplan, placement, CTS, routing)
- Final GDSII (tape-out ready)
- Detailed logs and reports
- Liberty models for timing analysis

**Why Excluded**:
- Specific to one design run/version
- Can be regenerated by running the full flow
- GDSII files are distribution-only, not for iterative development
- Size makes collaboration difficult

**How to Regenerate**:
```bash
cd vercore_sandbox/OpenROAD-flow-scripts
make clean
make DESIGN_CONFIG=designs/asap7/vercore/config.mk -j4
```

### 4. Simulation Outputs & Traces

**Paths**:
- `vercore_sandbox/rtl_trace.log`
- `vercore_sandbox/spike_trace.log`
- `vercore_sandbox/results/*.log`

**Size**: Few MB to hundreds of MB (depending on simulation length)

**Contents**:
- Instruction retire traces
- Signal value dumps
- Simulator stdout/stderr

**Why Excluded**:
- Temporary; specific to one test run
- Reproducible by re-running tests
- Takes up space when committing multiple runs
- Debugging artifacts (not production deliverables)

**How to Regenerate**:
```bash
cd vercore_sandbox
./build/sim_vercore build/test_basic.bin  # Generates rtl_trace.log
spike ... > spike_trace.log                # Generates spike reference
```

### 5. Verilator Generated C++ Files

**Paths**: `vercore_sandbox/build/obj_dir/`

**Size**: 50-200 MB

**Contents**:
- `Vvercore_top.cpp`, `Vvercore_top.h` - Generated C++ model
- `Vvercore_top_classes.mk` - Build metadata
- `*.o` files - Compiled C++ objects
- `verilated.cpp` - Verilator runtime

**Why Excluded**:
- Generated automatically by Verilator from Verilog
- Not human-editable
- Only needed during compilation
- Can grow very large for big designs

**How to Regenerate**:
```bash
cd vercore_sandbox
make clean
make build/sim_vercore  # Regenerates all Verilator files
```

### 6. Process Design Kit (PDK)

**Paths**: `vercore_sandbox/OpenROAD-flow-scripts/pdk/asap7/`

**Size**: 1-3 GB (potentially)

**Contents**:
- ASAP7 liberty files (timing libraries)
- Technology file (LEF)
- Standard cell models
- Metal layer definitions

**Why Excluded**:
- Licensed material from PDK vendor
- Should be downloaded directly from ASAP7 project
- Large; not practical for source control
- Version-specific; may change

**How to Install**:
```bash
# If using OpenROAD-flow-scripts:
cd vercore_sandbox/OpenROAD-flow-scripts
./setup.sh  # Downloads PDK automatically

# Or manually:
git clone https://github.com/The-OpenROAD-Project/asap7.git pdk/asap7
```

### 7. Debian Packages & Archives

**Patterns**: `*.deb`, `*.tar.gz`, `*.zip`, `*.tar.xz`

**Size**: Varies (10 MB - 1 GB each)

**Contents**:
- Downloaded tool installers
- Source archives
- Package management files

**Why Excluded**:
- Not needed; tools installed via `apt-get`
- Version control should track source, not installers
- Takes space unnecessarily

**How to Install**:
```bash
# Use package managers instead
sudo apt-get update
sudo apt-get install verilator yosys gcc-riscv64-unknown-elf
```

## 📝 Git Configuration for Large Files

### Using `.gitignore`

The `.gitignore` file excludes all patterns listed above. Key patterns:

```
# Build artifacts
build/
obj_dir/
*.o
*.a
*.so

# Large tools
vercore_sandbox/tools/
*.tar.gz
*.deb

# Simulation outputs
*.vcd
*.fst
rtl_trace.log
spike_trace.log

# OpenROAD outputs
results/
logs/
*.def
*.gds
```

### Best Practices

1. **Always run `make clean` before committing**:
   ```bash
   cd vercore_sandbox
   make clean
   git status  # Verify no build artifacts
   ```

2. **Check file sizes before adding**:
   ```bash
   git add <file>
   du -sh <file>  # Should be < 10 MB for most files
   ```

3. **Use `.gitattributes` for large tracked files** (if needed):
   ```
   *.gds filter=lfs diff=lfs merge=lfs -text
   ```

## 🔄 Workflow: What to Track vs. Exclude

### ✅ SHOULD be tracked in Git:

| Category | Example | Reason |
|----------|---------|--------|
| Source code | `.v`, `.S`, `.cpp` files | Human-written; needs version control |
| Configuration | `config.mk`, `.sdc`, `.ld` | Defines design parameters |
| Documentation | `.md` files, design notes | Human-created; tracks decisions |
| Scripts | `.sh`, `.py` (small) | Build automation |
| Test vectors | Small test files (<1 MB) | Reference data |

### ❌ SHOULD NOT be tracked:

| Category | Example | Reason |
|----------|---------|--------|
| Build outputs | `.o`, `.a`, executables | Auto-generated |
| Tool binaries | `/tools/*`, pre-built ELF | Platform-specific |
| Simulation outputs | `*.vcd`, `rtl_trace.log` | Temporary; reproducible |
| Large libraries | PDK files, GDSII | Externally sourced |
| IDE/editor files | `.vscode/`, `__pycache__` | Personal; not shared |

## 🚀 Repository Size Management

### Current Repository Size (Tracked Files Only)

```
RTL source code:       ~100 KB
Tests & testbenches:   ~50 KB
Documentation:         ~50 KB
Scripts:               ~30 KB
Configuration:         ~10 KB
─────────────────────────────
TOTAL:                 ~240 KB
```

**Git clone size**: ~500 KB (with .git history)

### With Build Artifacts (What NOT to commit)

```
Tracked files:         ~240 KB
Verilator build:       ~200 MB
OpenROAD results:      ~500 MB
Simulation traces:     ~100 MB
─────────────────────────────
TOTAL:                 ~800 MB (if accidentally committed!)
```

**Recommendation**: Use `make clean` before every commit.

## ♻️ Cleanup Script

```bash
#!/bin/bash
# Remove all excluded files

cd vercore_sandbox

# Clean build artifacts
make clean
rm -rf build/ results/ logs/

# Clean temporary files
rm -f rtl_trace.log spike_trace.log *.vcd *.fst

# Clean simulation results
rm -rf results/ rtl_results/ spike_results/

# Verify no large files remain
echo "Checking for remaining large files..."
find . -size +50M -type f | grep -v "\.git" || echo "None found ✓"
```

## 🤝 Contributing

When submitting pull requests:

1. Run `make clean` in `vercore_sandbox/`
2. Verify file sizes: `git diff --stat HEAD`
3. Ensure total PR < 10 MB
4. Exclude any `.deb`, `*.tar.gz`, binaries
